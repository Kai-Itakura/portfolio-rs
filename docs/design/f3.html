4 ルートが共有するトークン

この表が docs/design.md になります。@theme に置くのは色・フォント・角丸だけで、 余白とタイプスケールは Tailwind 既定のスケールに乗せられる値を選んであります。

トークン値使いどころ
--color-bg#000000地。ページ全体
--color-card#0A0A0Aカード・パネルの面。地との差は 4% だけ
--color-border#1F1F1F既定のボーダー。ほぼすべての区切りがこれ
--color-border-strong#333333ゴーストボタン、ピル、ホバー時の昇格先
--color-fg#EDEDED見出し・本文の既定色
--color-body#C6C6C6長い本文（作品詳細の about など）だけ一段落とす
--color-muted#A1A1A1補助テキスト、ラベル、タグ
--color-accent#E8913Cプロンプト記号、パス、年表の現在地、使用件数のブロック
--color-ok#62C073ステータスの緑。アクセントとは役割を分ける
--font-sansGeist本文・ボタン・カード
--font-monoGeist Mono見出し・ラベル・数値・パス・タグ
日本語Hiragino Sans → Yu Gothic → Noto Sans JP等幅にしない。字間は 0 に戻す
--radius6px / 10px / 999pxボタン / カード・パネル / ピル。3 段だけ
左右余白max(18px, 3cqw)SP で痩せすぎないよう下限を敷く
ブレークポイント860px / 620px要決定 — Tailwind 既定の md(768) / sm(640) とずれています

見出しが等幅である、というのがこのデザインの核です。Geist Mono 500 を letter-spacing: -0.03em で詰めて使います。等幅は 1 文字が広いので、 英字の短文にだけ使い、日本語の見出しには使いません。日本語で見出しが必要な箇所は font-size を上げずに font-weight: 600 で処理します。

前後ナビが片方しか出ていないのは仕様どおりです。 docs/architecture.md にあるとおり、旧サイトの並びは意図的に逆順で （prev = 次のインデックス、next = 前のインデックス）、端では空になってリンクが消えます。 sugutabe は order: 3 で末尾なので prev が空になり、左側の「next → sixhelmets」だけが出ます。 モックでは何が起きているかが分かるよう空スロットを点線で示していますが、 この挙動を踏襲するか、素直な前後に直すかは決めていません。下の未決事項に入れてあります。

open questions

実装前に決めておきたい 4 点

デザインは確定していますが、この 4 つは板倉さんの判断が要ります。どれも後から変えると波及が大きい箇所です。

  1. 前後ナビの並びを踏襲するか、直すか 旧サイトは prev と next が逆で、端で片方が消えます。 docs/architecture.md は「踏襲する」と書いていますが、Topcoat には getStaticPaths が無いので、どのみち計算場所を書き直すことになります。 直すなら、ついでに直すのが安いタイミングです。
  2. ブレークポイントを 620 / 860px のままにするか いまの値は Tailwind 既定の sm(640) / md(768) とずれています。 既存の ../portfolio は max-md:（767px）一本でした。 既定に寄せると max-md: だけで書けますが、860 → 768 に下げるとタブレット横で カードが 3 列のまま窮屈になります。
  3. コンテナクエリを使うか、@media にするか このモックはコンテナクエリで書いてあります（だから 390px のフレームに入れるだけで SP 表示が出せます）。 本番は @media のほうが素直です。Tailwind v4 は @container にも対応しているので、 カードなど再利用するコンポーネントだけコンテナクエリにする折衷もあります。
  4. Geist をバンドルするか、フォールバックで済ませるか 見出しが Geist Mono である前提のデザインなので、フォールバックすると印象がかなり変わります。 バンドルする場合、AssetBundle::load() は実行ファイルの隣の assets/ を読むので、 woff2 をバイナリと同じビルドから出す必要があります。ラテン文字だけのサブセットなら 2 ウェイトで 12KB 程度です。

next

ここから先

デザインの仕事はここまでです。以降は CLAUDE.md のとおり、実装は板倉さんが書きます。

  1. 未決の 4 点を決める特に前後ナビとブレークポイントは、書き始める前に決まっていないと手戻りします。
  2. docs/design.md を書く上のトークン表がそのまま中身になります。ご依頼があれば僕が書きます（docs/ は例外として許可されている範囲です）。
  3. @theme ブロックを作る色 9 個・フォント 2 つ・角丸 3 段。既存の global.css の @theme を置き換える形になります。
  4. 共通コンポーネントから書くナビ・ボタン・カード・タグ・フッターの 5 つが 4 ルート全部に出ます。ここが固まればページは組み立てるだけです。
  5. ルートは / → /works → /works/{slug} → /about の順で詳細ページが最も難しいので、一覧で作品データの取り回しに慣れてから入るのが楽です。
  6. 詰まったら聞いてくださいヒントとレビューで入ります。答えではなく次の一歩を返します。
