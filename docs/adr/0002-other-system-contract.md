# 別システムとの契約はこのサイトのドメインに合わせ、同期で翻訳する

案件と技術は別システムから届くが、別システムはこのサイトより後に固まる見込みなので、
別システムの契約（API の形）をこのサイトのドメインモデルに合わせて作る（顧客・供給者の関係）。
それでもドメインは契約に依存させない。同期のコードが届いたデータをドメインの型へ翻訳し
（腐敗防止層）、名前の違いはそこで吸収する。翻訳で吸収できない食い違いが出たら、
ドメインか契約のどちらかを直す。このサイトが先に固まるので、ふつうは契約の側を直す。

## Consequences

- カテゴリ名の違い（別システムの「フレームワーク」と `Category::Framework`）は翻訳で対応させ、ドメインは変えない
- 5 つにないカテゴリが届いたら、契約違反として翻訳でエラーにする。`Category` には足さず、契約の側を直す
- まだ計画の段階で、別システムが先に固まるなどして前提が崩れたら見直す
