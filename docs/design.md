# デザイン（決定事項）

移植後のビジュアル仕様。**実装前のスペックであり、実装そのものではない。**
ここに書かれた値に沿って、コードはオーナーが自分で書く。

- 出典: F3 案（全 4 ルートの PC / SP モック）— https://claude.ai/artifact/H59sKWnJyFady3NHffwUwu
- 構成・ルーティング・データの扱いは [`architecture.md`](architecture.md) を見ること。
  このファイルは**見た目のトークンと各ルートのレイアウト**だけを扱う

## 決定事項（2026-09-19）

レスポンシブの方式・ブレークポイント・前後ナビ・フォントの 4 点は、以下で確定している。

| | 決定 | 理由 |
| --- | --- | --- |
| レスポンシブの方式 | **`@media` 一本**。`container-type` はどこにも付けない | モックの `@container` はモック枠をビューポートの代役にしていただけで、コンポーネント単位のコンテナクエリは元から存在しない。必要になった時点で個別に昇格させれば足りる |
| ブレークポイント | **620 / 860px を維持**。`@theme` で `--breakpoint-sm` / `--breakpoint-md` を上書きする | 既定（640 / 768）に寄せると 860 → 768 に下がり、タブレット横でカードが 3 列のまま窮屈になる。上書きすれば `max-md:` の書き味は既定のまま使える |
| 作品詳細の前後ナビ | **`prev` が前、`next` が次**（旧サイトの逆転は引き継がない） | `getStaticPaths` が無い以上どのみち計算を書き直すので、直すならいまが一番安い |
| Geist / Geist Mono | **バンドルする** | 見出しが等幅であることがこのデザインの核であり、フォールバックすると印象が変わる。ラテンサブセット 2 ウェイトで約 12KB |

## トークン

`@theme` に置くのは**色・フォント・角丸・ブレークポイント**だけ。
余白とタイプスケールは Tailwind 既定のスケールに乗る値を選んであるので、トークン化しない。

### 色（9 個）

| トークン | 値 | 使いどころ |
| --- | --- | --- |
| `--color-bg` | `#000000` | 地。ページ全体 |
| `--color-card` | `#0A0A0A` | カード・パネルの面。地との差は 4% だけ |
| `--color-border` | `#1F1F1F` | 既定のボーダー。ほぼすべての区切りがこれ |
| `--color-border-strong` | `#333333` | ゴーストボタン、ピル、ホバー時の昇格先 |
| `--color-fg` | `#EDEDED` | 見出し・本文の既定色 |
| `--color-body` | `#C6C6C6` | 長い本文（作品詳細の about など）だけ一段落とす |
| `--color-muted` | `#A1A1A1` | 補助テキスト、ラベル、タグ |
| `--color-accent` | `#E8913C` | プロンプト記号、パス、年表の現在地、使用件数のブロック |
| `--color-ok` | `#62C073` | ステータスの緑。アクセントとは役割を分ける |

ダーク一色。テーマ切り替えは持たない（＝クライアント状態が要らない）。

旧 `global.css` の `@theme` にあった `--color-main` / `--color-accent` と、
コード中に散っていた生値（`#F08774` / `cadetblue` / `#5BAE6D` / `#facf63` /
`#F08275` / `#333` / `rgb(58 61 62 / 0.5)`）は、すべてこの 9 個に集約して捨てる。

### フォント

| トークン | 値 | 使いどころ |
| --- | --- | --- |
| `--font-sans` | Geist | 本文・ボタン・カード |
| `--font-mono` | Geist Mono | **見出し**・ラベル・数値・パス・タグ |
| （日本語） | Hiragino Sans → Yu Gothic → Noto Sans JP | 等幅にしない。字間は `0` に戻す |

**見出しが等幅である、というのがこのデザインの核。**
Geist Mono 500 を `letter-spacing: -0.03em` で詰めて使う。
等幅は 1 文字が広いので、**英字の短文にだけ**使い、日本語の見出しには使わない。
日本語で見出しが必要な箇所は `font-size` を上げずに `font-weight: 600` で処理する。

配信方法はバンドル。**Geist / Geist Mono は Fontsource のカタログにあるので、
`font-fontsource` feature の `fontsource_font!` に `host: Asset` を付ければ、
ビルド時にダウンロードして自分のオリジンから配信される。**
サブセットとウェイトはマクロの引数で絞る（`subset: Latin` / `weight: [...]`）ので、
woff2 を手で用意してサブセット化する必要は無い。

| id | family | 利用可能なウェイト |
| --- | --- | --- |
| `geist` | Geist | 100–600（可変） |
| `geist-mono` | Geist Mono | 100–600（可変） |

上で要求している Geist Mono 500 と Geist 600 は両方とも範囲内。

実体は Topcoat のアセットになるので、[`topcoat-notes.md`](topcoat-notes.md) の
アセットの節にあるハマりどころ（未使用ハンドルは最適化で消える / バイナリとバンドルは
同じビルドから出す / バンドルに無いアセットはパニックする）がそのまま当てはまる。

### 角丸（3 段だけ）

| 値 | 使いどころ |
| --- | --- |
| `6px` | ボタン |
| `10px` | カード・パネル |
| `999px` | ピル |

### ブレークポイント

| 名前 | 値 | 境目で起きること |
| --- | --- | --- |
| `md` | `860px` | カードのグリッドが減る。ナビがドロワーになる |
| `sm` | `620px` | 1 列に落ちる。ヒーロー・フッター・年表が SP 組みになる |

`@theme` で `--breakpoint-md` / `--breakpoint-sm` を上書きして、
記述は Tailwind 既定の `max-md:` / `max-sm:` のまま使う。

## 🔴 `cqw` → `vw` の読み替えが要る

モックは流動的な余白とタイプスケールにコンテナクエリ単位（`cqw`）を使っている。
`@media` 一本に決めた以上、**`cqw` はコンテナの外では無効なので `vw` に読み替える**必要がある。

| 箇所 | モックの値 |
| --- | --- |
| 左右余白 `--pad` | `max(18px, 3cqw)` |
| ヒーローの上下 padding | `max(42px, 5.4cqw)` / `max(38px, 5cqw)` |
| ヒーロー見出し | `clamp(24px, 4.4cqw, 50px)`（SP は `clamp(22px, 7.4cqw, 30px)`） |
| ブロックの padding | `max(34px, 4.4cqw)` |
| セクション見出し | `clamp(19px, 2.2cqw, 26px)` |
| 作品詳細の 2 カラム gap | `3cqw` |

**単純な置換では合わない。** モックの `cqw` はモック枠（最大 1272px）基準だが、
`vw` はビューポート全幅基準なので、ワイドな画面ほど値が大きく出る。
たとえば 1512px 幅なら `5.4cqw` = 約 69px に対し `5.4vw` = 約 82px。
`clamp()` の上限に当たる見出しは吸収されるが、余白系はずれる。

係数を掛けて調整するか、ページ側に最大幅を敷いて `min()` で頭を押さえるか、
どちらかの判断が要る。**値をそのまま `vw` に書き換えるのは誤り。**

## 共通コンポーネント

4 ルート全部に出る 5 つ。ここが固まればページは組み立てるだけになる。

| | 備考 |
| --- | --- |
| ナビ | 860px 以下でドロワー。開閉は `<input type="checkbox">` + `:has()` の CSS のみ。**JS は使わない** |
| ボタン | ソリッドとゴーストの 2 種。SP では CTA が `flex: 1` で画面幅いっぱい |
| カード | `/`（3 列）・`/works`（2 列）・`/about` の Hobby（3 列）で使い回す |
| タグ | ピル。`tools[]` から出す。折り返すだけでブレークポイントを持たない |
| フッター | 620px 以下で縦積み |

**このデザイン全体でクライアントサイドの状態はゼロ。**
モックには `<script>` が 1 つも無く、ドロワーも CSS だけで動いている。
Topcoat の `$(...)` 式も Islands も使わずに成立する。

## ルート別

### `/` — トップ

| | |
| --- | --- |
| 構成 | ヒーロー → Works（3 列） → 使用件数 → フッター |
| 見出し | Geist Mono 500 / PC 50px → SP 30px |
| データ | `works` を `order` 昇順で全件。3 件しかないので「もっと見る」は `/works` へ |
| SP | カード 1 列（画像 16:10 → 16:9）、CTA は画面幅いっぱい、使用件数 2 列 → 1 列 |

ヒーローは `$ whoami` の出力という見立てで、`base` / `stack` / `status` / `this site` の 4 行。
**スクロールせずに「誰が・何ができて・いま何をしているか」が読める**ところまでを 1 画面に入れる。
旧サイトの 100vh ベタ塗り + 筆記体の名前を置き換える。

SP では kv リストのラベル列を 72px 固定にし、日本語の値は 2 行に折り返す。

### `/about` — 経歴とスキル

| | |
| --- | --- |
| 構成 | ヒーロー → Profile → 年表 → 使用件数 → Hobby → フッター |
| 新規 | 年表（`.timeline`）とプロフィール 2 カラムの 2 つだけ |
| 再利用 | ヒーロー・カード・使用件数・フッターはトップと同一 |
| データ | 年表は静的。Hobby は旧サイトの 3 件をそのまま |
| SP | プロフィールは縦積み（写真 190px）、Hobby は 1 列、年表は変更なし |

**旧サイトのスキルバーは廃止する。** 「60〜80%」という自己申告の数値は読み手にとって
情報量がゼロだった。代わりに置くのは年表（事実の列なので検証できる）と
使用件数（`tools[]` から自動で出る）。現在地だけアクセント色の点が付く。

副次的に、IntersectionObserver によるカウントアップという JS 依存もここで消える。

**要検討:** SP だとページがかなり縦に長くなる（年表 7 項目 + 使用件数 10 行 + Hobby 3 件）。
Hobby を折りたたむか、`/about` をさらに分けるかの判断が残っている。

### `/works` — 作品一覧

| | |
| --- | --- |
| 構成 | ヒーロー（件数付き） → カード 2 列 → フッター |
| 新規 | カードの `.took` 行（`tools` / `time`）だけ |
| 並び | `order` の昇順。トップと同じ |
| SP | 2 列 → 1 列（画像 16:9）。`.took` と説明文はそのまま残す |

トップの Works セクションとの差は**情報量**。3 列 → 2 列で画像を大きく取り、
カードの下に `tools` と `time` を出すことで、詳細を開かずに判断できるようにする。

作品が 3 件しかないので、**グリッドを埋めようとしない。**
2 列にすると 3 件目が左に 1 つ残るが、これは欠落ではなく「3 件です」という事実の表示。
件数をヒーローに明記して、意図であることをはっきりさせる。

SP で 1 列になると、トップの Works セクションとの差が「説明文とタグの量」だけになる。
そこが `/works` の存在理由なので、**SP でも説明文を削らない。**

### `/works/{slug}` — 作品詳細

| | |
| --- | --- |
| 構成 | パンくず → タイトル → 帯画像 → 本文 + メタ（2 カラム） → モックアップ → スクショ 2 枚 → 前後ナビ |
| 新規 | パンくず・帯画像・`.metadl`・`.plate`・前後ナビ |
| 画像比率 | 帯 16:7 / モック 16:9 / スクショ 3:4。全部固定値 |
| 本文 | Markdown。色は `--color-body` |
| SP | 帯画像のみ 16:7 → **3:2**。本文 + メタは縦積み（本文が先）。スクショは縦積みで 3:4 維持。前後ナビ 1 列 |

4 ルートで唯一、SP のために比率を変えている画像がある。帯画像を 16:7 のままにすると
SP で高さ 170px しか出ず、何が写っているか分からなくなるため。

パンくずは `works / sugutabe` の形で、実際のルートと一致させる。

**旧サイトの `h-[200vw]` は廃止する。** `image1` / `image2` は `aspect-ratio: 3/4` の窓に
上端を合わせて表示する。元画像が縦に長い全ページスクショなので、窓のサイズを明示するのが
正しい扱い。キャプションに実寸を出して、切り取りであることを隠さない。

前後ナビは端で片方が空になり、そちらのリンクは表示しない。
**空スロットの点線は SP では消す。**

## 画像比率の一覧

| 用途 | PC | SP |
| --- | --- | --- |
| カード（トップ） | 16:10 | 16:9 |
| カード（`/works`） | 16:9 | 16:9 |
| Hobby | 4:3 | 4:3 |
| 帯画像（詳細） | 16:7 | **3:2** |
| モックアップ | 16:9 | 16:9 |
| スクショ（`image1` / `image2`） | 3:4 | 3:4 |

Topcoat に画像最適化は無いので、webp への変換とサイズ調整は事前に自分でやる。
比率が全部固定値なので、`srcset` を組まなくても破綻しない設計にしてある。

## 実装順

1. `@theme` ブロック（色 9 / フォント 2 / 角丸 3 / ブレークポイント 2）
2. 共通コンポーネント 5 つ（ナビ・ボタン・カード・タグ・フッター）
3. ルートは `/` → `/works` → `/works/{slug}` → `/about` の順

詳細ページが最も決めることが多いので、一覧で作品データの取り回しに慣れてから入る。
`/about` を最後にするのは、年表とプロフィールがこのページ専用で、
他に影響しないため（先に共通部分を固めたほうが得）。
